# Reproducing and verifying the examination package

The release preserves existing analysis outputs and their exact source snapshots. Verify the frozen files **before** rebuilding: a rebuild may change timestamps or container-level GeoPackage bytes even when scientific values agree. Planned models are not part of this reproduction route.

## 1. Environment and frozen inputs

From the repository root, use Python 3.12:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-spatial.txt
python tools/restore_tree_inventory.py
python tools/verify_examination.py
```

The restore step uses Python's standard library and validates both compressed and uncompressed hashes. It refuses to overwrite a different local inventory. Allow about 335 MB for the restored file in addition to the checkout. No live source refresh is needed. The archive's original source acquisition history remains incomplete; its identity is fixed by SHA-256.

The spatial requirements are pinned. These are analysis dependencies, not a complete operating-system lockfile. The actual tested environment and verification results are in [validation.md](validation.md).

## 2. Validate existing products

```bash
PYTHONPATH=src python -m berlin_heat status
PYTHONPATH=src python -m berlin_heat validate
PYTHONPATH=src python -m unittest discover -s tests -v
```

Warnings about source CRS, denominator limitations, missing historical inputs and unverified LST processing are intentional. A successful contract check does not establish scientific validity of a planned model. `status` reports the current October design and missing dependencies.

## 3. Rebuild the descriptive notebooks

The frozen LOR and equity inputs are already included. Do not run the live equity downloader when reproducing the exact release; it would obtain a later source state.

```bash
python analysis/build_exploratory_notebook.py
jupyter nbconvert --to notebook --execute output/jupyter-notebook/berlin-urban-heat-exploration.ipynb --inplace --ExecutePreprocessor.timeout=1200
python analysis/build_spatial_notebook.py
jupyter nbconvert --to notebook --execute output/jupyter-notebook/berlin-lor-spatial-watering.ipynb --inplace --ExecutePreprocessor.timeout=1200
python analysis/build_equity_notebook.py
jupyter nbconvert --to notebook --execute output/jupyter-notebook/berlin-lor-equity-environment.ipynb --inplace --ExecutePreprocessor.timeout=1200
```

These produce the source audits, district/LOR descriptive products, Moran statistics, equity tables and geospatial outputs. Local Moran classifications use seed 42; inferential limits remain documented in the atlas. Run in the stated order because later notebooks consume earlier products.

## 4. Rebuild temporal and weather products

```bash
python pipelines/03_build_lor_month_panel.py
python pipelines/04_build_watering_temporal_atlas.py
python pipelines/05_build_recorded_tree_day.py
python analysis/build_watering_response_report.py
```

The final command builds monthly weather results and incorporates the supplied Ortsteil file when present. The Ortsteil extension remains provisional. The existing tests cover keys, totals, missingness, monthly lag alignment, duplicate-outcome handling, residualisation and calendar-aware uncertainty.

## 5. Rebuild the examination PDFs and inventories

```bash
python -m pip install -r requirements-examination.txt
python tools/build_examination.py
python tools/verify_examination.py
```

The builder assembles twelve saved map images into an atlas, produces a four-page brief, reads headline findings from tables, inventories the available data and refreshes the release manifest. It does not refit scientific models or revise the proposal. The two canonical proposal/presentation PDFs and the workbook are preserved source deliverables and are not regenerated by this command.

After a deliberate documentation-only change, refresh the exact-file manifest with `python tools/build_examination.py --manifest-only`. Do not refresh it to conceal an unexplained data discrepancy.

## Optional Office authoring

The included workbook is directly readable in Excel or LibreOffice. The original workbook scripts use `@oai/artifact-tool` and require that optional authoring environment, selected with `WATERING_ARTIFACT_NODE_MODULES`. They are not a dependency for the Python scientific pipeline. All underlying analysis tables and JSON workbook inputs are included independently.

`tools/apply_*proposal*.py`, `tools/revise_proposal_must_cites.py`, `tools/build_feedback_integrated_proposal.py` and `tools/update_proposal_slides.mjs` are historical August authoring utilities. They do not rebuild the October proposal and may require local feedback files. Do not use them for this submission. The portable verification suite does not require private files from Downloads.

## What is not reproduced

The proposed balanced daily model, historical young-tree eligibility, vegetation cooling-loss model, predictive calibration, allocation comparison and bridge test are prospective. The supplied proposal's Appendix A is design rationale, not an independently reproduced experiment in this package. External basemap tiles are also not frozen; use the static atlas for a stable review.
